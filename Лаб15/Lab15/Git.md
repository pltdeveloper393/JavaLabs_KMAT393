# Git: контрольные вопросы и работа с репозиторием

## Контрольные вопросы

**1. Что такое система контроля версий и почему она нужна?**
Система контроля версий (VCS) — программа, которая записывает изменения в файлы со временем и позволяет вернуться к любой прежней версии. Нужна, чтобы не бояться ломать код: можно откатиться, посмотреть историю изменений и не потерять файлы при сбоях.

**2. Чем отличается Git от других систем контроля версий (SVN, Perforce)?**
Git — распределённая система: у каждого разработчика полная копия репозитория со всей историей, поэтому работа идёт офлайн и любой клиент способен восстановить проект. В централизованных SVN и Perforce история хранится только на одном сервере. Кроме того, Git хранит снимки всего проекта, а не список различий по файлам.

**3. В каких трёх состояниях могут находиться файлы в Git?**
- Modified (изменён) — файл изменён, но не зафиксирован;
- Staged (подготовлен) — изменения отмечены для следующего коммита;
- Committed (зафиксирован) — изменения сохранены в локальную базу.

**4. Какие основные команды Git вы знаете?**
git init, git clone, git status, git add, git commit, git log, git diff, git branch, git checkout, git merge, git pull, git push, git revert, git reset.

**5. Что такое ветка в Git и зачем она нужна?**
Ветка — независимая линия разработки, указатель на коммит. Нужна, чтобы работать над отдельной задачей, не затрагивая стабильный код, и вести параллельную разработку. Основные команды: git branch, git checkout -b, git merge.

**6. Что такое конфликт слияния и как его разрешить?**
Конфликт возникает, когда две ветки изменили одну и ту же часть файла по-разному. Git помечает спорные участки маркерами <<<<<<<, =======, >>>>>>>. Нужно вручную оставить нужный вариант, убрать маркеры, затем выполнить git add и git commit.

**7. Что такое GitHub и чем он отличается от Git?**
Git — локальная система контроля версий. GitHub — облачная платформа для размещения удалённых репозиториев Git: доступ к коду из интернета, совместная работа, ревью и Pull Request.

**8. Что такое Pull Request и зачем он нужен?**
Pull Request — предложение внести изменения в репозиторий: ветка запушена, на GitHub описано, что изменено, изменения проходят проверку и после одобрения сливаются в основную ветку обычным merge с отдельным коммитом слияния.

**9. Что такое файл .gitignore и зачем он нужен?**
.gitignore — список файлов и папок, которые Git не отслеживает: скомпилированные файлы (.class, .jar, target/), настройки IDE (.idea/, *.iml), служебные файлы операционной системы и логи.

## Кратко о работе с репозиторием

Git хранит снимки (snapshots) состояния проекта: каждый коммит ссылается на полное состояние файлов. Жизненный цикл изменений: правишь файл (modified) → добавляешь в индекс git add (staged) → фиксируешь git commit (committed).

Ветки в Git — дешёвые указатели на коммиты: новая ветка создаётся мгновенно, а переключение между ними не копирует проект заново. Слияние git merge соединяет линии разработки, а с ключом --no-ff всегда создаётся отдельный коммит слияния, поэтому в истории видно, какая работа и когда была принята в основную ветку.

Удалённый репозиторий (origin) — копия проекта на сервере. Связь задаётся командой git remote add, изменения отправляются через git push, а забираются через git fetch и git pull.

## Команды, использованные при переносе лабораторных работ

```bash
# создание репозитория и корневой коммит
git init -b main
git add .gitignore .gitattributes
git commit -m "chore(repo): инициализирован репозиторий"
git remote add origin https://github.com/pltdeveloper393/JavaLabs_KMAT393.git
git push -u origin main

# для каждой лабораторной работы
git checkout -b lr1 main
git add "Лаб1"
git commit -m "feat(lr1): добавлена лабораторная работа 1"
git push -u origin lr1
# далее Pull Request на GitHub: Compare & pull request -> Create pull request
# после проверки: Merge pull request -> Confirm merge (Create a merge commit)

# перед следующей работой основная ветка обновляется
git checkout main
git fetch origin
git reset --hard origin/main

# проверка истории
git log --graph --oneline --all
```
